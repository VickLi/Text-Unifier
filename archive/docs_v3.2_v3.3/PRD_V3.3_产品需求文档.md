| **版本类型** | 功能增强 + 交互优化 |
| **目标平台** | Windows / macOS 桌面端（Electron + napi-rs） |

## 版本概述

V3.3 聚焦 **交互打磨**——解决 V3.2 遗留的 9 项体验缺陷，引入预览条（段落指示器）、双向转换按钮、关键词搜索删除等新交互。

| 编号 | 需求 | 类型 | 用户痛点 |
| :---: | :--- | :--- | :--- |
| RQ-01 | 文件芯片栏按钮对齐 | Bug 修复 | "添加txt文件"按钮换行撑高整个栏 |
| RQ-02 | 全局 Tooltip 补充 | 交互增强 | 文件名被截断、重复段落文字被截断，无法看到完整内容 |
| RQ-03 | 文件增删时自动刷新重复组 | Bug 修复 | 删除文件后左侧列表不更新 |
| RQ-04 | 预览条 + 删除段落保留 | 新功能 | 无法直观看到哪些段落被删除/修改/保留了 |
| RQ-05 | 清洗面板双向切换按钮 | 交互重构 | Checkbox 开关不够直觉，要明显看到转换方向 |
| RQ-06 | 关键词搜索下一个 + 一键删除 | 新功能 | 广告过滤只能全量删除，无法定向控制 |
| RQ-07 | 移除行尾页码功能 | 功能精简 | 实用性低，误开启风险 |
| RQ-08 | 工具修改预览条橙色标记 | 新功能 | 不知道哪些段落被右侧工具修改了 |
| RQ-09 | 导出保留撤销栈 | 交互增强 | 导出后无法还原，发现错误只能重来 |

## 1. 功能边界

### 1.1 做什么

#### RQ-01：文件芯片栏按钮对齐

- 文件芯片栏末尾的「+ 添加 .txt 文件」按钮宽度固定为芯片相同高度（36px × 36px 方形图标按钮）
- 按钮不再显示完整文字，改为 `+` 图标 + Tooltip（悬停显示"添加 .txt 文件"）
- 文件芯片行内所有元素等高 36px，按钮不会因文字折行撑高

#### RQ-02：全局 Tooltip 补充

- **重复段落列表**：鼠标悬停重复组 `snippet` 区域 → 浮层显示完整段落文字（前 200 字 + "..."）
- **文件芯片**：鼠标悬停芯片文件名 → 浮层显示完整文件名（无截断）
- Tooltip 触发方式：hover 300ms 延迟，避免频繁弹出
- Tooltip 样式：白色底圆角卡片，灰色边框，跟随鼠标 + 8px 偏移

#### RQ-03：文件增删自动刷新重复组

- 用户拖入新文件 → 重新分析 → 自动更新左侧重复组列表
- 用户删除文件 → 移除该文件对应的所有重复组记录 → 重新计算 occurrenceCount → 更新重复组列表
- 删除文件后，`occurrence_count` 变为 1 的重复组不再显示（V1.1 规则：仅跨文件重复才展示）
- 刷新时保留用户已勾选的重复组状态（基于 `content_hash` 匹配恢复）

#### RQ-04：预览条 + 删除段落保留展示

**段落状态指示器（彩色竖线）**：
- 每个段落左侧有 3px 宽的彩色竖线
  - 绿色 `border-l-green-500` → 正常段落（已勾选保留）
  - 红色 `border-l-red-400` → 已删除段落（取消勾选 / 重复组排除）
  - 橙色 `border-l-orange-400` → 被工具修改过的段落（RQ-08）

**Minimap 缩略图**：
- 预览区最右侧，30px 宽的细长柱状图
- 每一段对应一个色条（2px 高 + 1px 间距）
- 颜色与段落状态指示器一致（绿/红/橙）
- 鼠标悬停色条 → 高亮变色条 → 对应段落滚动入视野
- 单击色条 → 跳转到该段落

**已删除段落展示**：
- 取消勾选的段落**不再隐藏**，保留在预览中
- 样式：删除线 `line-through` + 文字灰色 `text-gray-400` + 不透明度 `opacity-50`
- Checkbox 显示为未勾选状态
- 左侧指示器为红色

#### RQ-05：清洗面板双向切换按钮

- **全角↔半角** 按钮：
  - 初始状态：「全角→半角」（蓝色按钮，箭头向右）
  - 点击后立即执行全角→半角转换 + 按钮变为「半角→全角」（箭头向左）
  - 再点击执行半角→全角转换 + 按钮恢复为「全角→半角」
  - 本质是 toggle：文本在"已转换"和"未转换"之间切换

- **繁简转换**按钮：
  - 初始状态：「繁→简」（蓝色按钮，箭头向右）
  - 点击后立即执行繁→简转换 + 按钮变为「简→繁」（箭头向左）
  - 再点击执行简→繁转换 + 按钮恢复为「繁→简」
  - 移除原来的 select 下拉框

> **底层逻辑**：按钮不维护转换历史——它只是对当前文本的方向操作。两次点击 = 来回转换 = 回到原文（OpenCC 实现了无损往返）。

#### RQ-06：关键词搜索下一个 + 一键删除

- 在过滤关键词输入框下方新增两个按钮：
  - **🔍 搜索下一个**：从预览区当前光标位置开始，查找下一个包含任一关键词的行，滚动到该行并高亮（黄色背景 `bg-yellow-200`）。连续点击依次跳转。
  - **🗑 一键删除**：直接删除预览中所有包含任一关键词的行（`filterLines` 全量移除）
- 搜索高亮在 3 秒后自动消退（`setTimeout` 移除高亮类名）
- 两个按钮独立操作：搜索不触发删除，一键删除不依赖搜索

#### RQ-07：移除行尾页码功能

- 从 CleanPanel 中移除「清除行尾页码」Checkbox
- 从 `CleanOptions` 类型中移除 `removeLineEndNumbers` 字段
- 从处理流水线中移除 `removeLineEndNumbers()` 调用

#### RQ-08：工具修改预览条橙色标记

- 右侧工具面板的任何操作（清洗预处理、章节工具、排版增强）执行后
- 被修改段落在预览中的 `modifiedByTool` 标记设为 `true`
- 段落左侧指示器变为**橙色** `border-l-orange-400`
- Minimap 中对应色条变为橙色
- 橙色标记在用户「重新开始」或「导入新文件」时清除

> **判定"被修改"的逻辑**：排版前后段落文本 `text` 字段发生变化 → `modifiedByTool = true`。

#### RQ-09：导出保留撤销栈

- 当前 V3.2 的 5 步撤回栈在以下情况才清空：
  - 用户点击「重新开始」
  - 用户拖入新文件触发重新分析
- **导出操作不清空撤回栈**
- 导出按钮旁新增「↶ 还原至上一次」按钮（与撤回栈独立的小型还原按钮）
- 导出前的最后一步操作可通过 Ctrl+Z / 还原按钮撤销

### 1.2 不做什么

- Minimap 不支持鼠标拖拽滚动（仅点击跳转）
- 关键词搜索不跨文件搜索（仅在当前预览文本中搜索）
- 双向切换按钮不维护独立的状态历史（纯 toggle 逻辑）
- 预览条颜色不与导出文件内容关联（仅 UI 层显示）

## 2. 核心业务逻辑

### 2.1 删除文件后重复组更新算法

```python
def on_remove_file(removed_path: str, duplicate_groups: list, sorted_files: list):
    """删除文件后重新计算重复组列表"""

    # Step 1: 从所有重复组的 sources 中移除该文件的条目
    for group in duplicate_groups:
        group.sources = [s for s in group.sources if s.file_name != removed_path]
        # 重新计算涉及的文件数
        unique_files = set(s.file_name for s in group.sources)
        group.occurrence_count = len(unique_files)

    # Step 2: 过滤掉只涉及 ≤1 个文件的重复组
    duplicate_groups = [g for g in duplicate_groups if g.occurrence_count > 1]

    # Step 3: 保留用户勾选状态（基于 content_hash 匹配）
    # 已在 store 中通过 paragraphCheckedMap 维护
    return duplicate_groups
```

### 2.2 段落状态指示器颜色判定

```python
for paragraph in preview_paragraphs:
    if not paragraph_checked_map[paragraph.id]:
        color = RED    # 被取消勾选
    elif paragraph.modified_by_tool:
        color = ORANGE # 被工具修改过
    else:
        color = GREEN  # 正常段落
```

优先级：红色 > 橙色 > 绿色（被删除的段落即使被工具修改也显示红色）。

### 2.3 双向切换按钮逻辑

```text
按钮初始状态: [全角→半角]  文本状态: 原文
       │
       ▼ 点击
执行 toHalfWidth(text) → text′
按钮状态: [半角→全角]  文本状态: 已转换
       │
       ▼ 再点击
执行 toFullWidth(text′) → text″ ≈ 原文
按钮状态: [全角→半角]  文本状态: 恢复原文
```

> 繁简转换同理：`繁→简` ⇄ `简→繁`。

### 2.4 关键词搜索下一个

```python
def search_next_keyword(text: str, keywords: list[str], current_pos: int) -> int | None:
    """从 current_pos 开始搜索下一个匹配行，返回该行起始位置"""
    lines = text.split('\n')
    accumulated = 0
    for i, line in enumerate(lines):
        line_start = accumulated
        line_end = accumulated + len(line)

        # 跳过当前位置之前的行
        if line_end <= current_pos:
            accumulated = line_end + 1  # +1 for \n
            continue

        # BUG-V3.3-001: handle wrap-around (search from beginning)
        for kw in keywords:
            if kw and kw in line:
                return line_start

        accumulated = line_end + 1

    # 未找到，从头循环
    return search_next_keyword_from_beginning(text, keywords)
```
